# 产品经理 (Product Manager) Skill

**核心原则：以用户价值和商业目标为导向，明确问题本质，精简定义 MVP，数据驱动决策。**

## 何时使用

- 启动新产品、新功能或重构现有业务模块时
- 需要梳理产品定位、目标用户画像及核心价值主张时
- 进行竞品分析、行业对标及差异化策略制定时
- 评估与排定需求优先级（如 RICE、Kano 模型、MoSCoW）时
- 设计用户旅程图（User Journey Map）或用户故事地图（Story Mapping）时
- 定义产品北极星指标、业务衡量指标及数据埋点方案时

---

## 核心工作流与操作步骤

### 1. 明确问题定义与目标用户 (Problem & User Persona)
1. **背景与痛点**：明确当前解决的是谁的什么问题？发生场景与频率为何？
2. **目标群体画像**：
   - 核心用户角色（Persona）、使用场景（Context）、现有替代方案（Current Workarounds）。
3. **价值主张**：该功能/产品带来什么独特价值？（效率提升、体验优化、成本降低等）。

### 2. 竞品与市场分析 (Competitive Analysis)
- 选取直接竞品、间接竞品与行业标杆。
- 从**功能完整度**、**交互体验**、**商业模式**、**技术/数据壁垒**四个维度进行横向对比（SWOT / 功能矩阵）。
- 提炼出本产品的**核心差异化优势（Differentiators）**。

### 3. MVP 范围定义与优先级评估 (Scope & Prioritization)
- 使用 **RICE 评估法** 对功能进行量化排序：
  $$\text{RICE Score} = \frac{\text{Reach (覆盖人数)} \times \text{Impact (影响程度)} \times \text{Confidence (置信度)}}{\text{Effort (开发人月/复杂度)}}$$
- 或使用 **MoSCoW 原则** 划分范围：
  - **Must-have**：MVP 核心闭环必不可少的功能
  - **Should-have**：重要但不影响当前版本上线的功能
  - **Could-have**：体验加分项，资源充足时实施
  - **Won't-have**：本期明确不做，放入后续 Backlog

### 4. 用户旅程与故事地图 (User Journey & Story Mapping)
- 梳理主流程干线（User Flow Backbone）：
  - 认知/触发 $\rightarrow$ 接入/注册 $\rightarrow$ 核心价值体验 $\rightarrow$ 留存/转化 $\rightarrow$ 分享/推荐
- 识别各环节的**触点、用户心理感受、潜在痛点与机会点**。

### 5. 指标体系与衡量标准 (Metrics & Success Criteria)
- **北极星指标 (North Star Metric)**：衡量产品核心价值被用户消费的关键指标。
- **过程/衡量指标**：
  - 激活率、转化率、留存率、任务完成耗时、错误率等。
- **定性指标**：用户满意度（CSAT / NPS）、用户反馈收集机制。

## 标准输出模板

### 产品概念与规划提案 (Product Brief)

```markdown
# [产品/功能名称] 产品方案规划

## 1. 背景与核心价值
- **问题定义**：[描述痛点及现状]
- **目标用户**：[主要受众与特征]
- **核心价值**：[带来的收益]

## 2. 竞品分析与差异化
| 维度 | 竞品 A | 竞品 B | 本产品方案 |
| :--- | :--- | :--- | :--- |
| 核心功能 | ... | ... | ... |
| 优势/亮点 | ... | ... | ... |
| 不足/痛点 | ... | ... | ... |

## 3. MVP 功能清单与优先级 (MoSCoW)
- 🔴 **Must Have (MVP 必备)**:
  1. [功能项 1]: [简述]
  2. [功能项 2]: [简述]
- 🟡 **Should Have (本期建议)**:
  1. [功能项 3]: [简述]
- ⚪ **Won't Have (后续规划)**:
  1. [功能项 4]: [简述]

## 4. 核心用户旅程与业务流程
1. [步骤 1]: [操作与系统反馈]
2. [步骤 2]: [操作与系统反馈]
3. [步骤 3]: [核心价值闭环]

## 5. 成功衡量指标 (Metrics)
- **核心指标 (NSM)**: [例如：周均生成高质量考卷数]
- **辅助指标**: [例如：首屏响应时间 < 2s, 用卷转化率 > 30%]
```

## 注意事项

1. **避免过度设计**：MVP 阶段坚决砍掉非核心逻辑，以最小代价验证关键假设。
2. **区分“用户想要的”与“用户需要的”**：关注底层动机而非表面诉求。
3. **保持技术可行性认知**：在提出方案前与研发/架构师对齐可行性边界与复杂度。
