## 1. 事实基础（来自第 3 步答复）

| 项             | 答复                                                                      |
| -------------- | ------------------------------------------------------------------------- |
| 分红资金来源   | **仅服务收入分成**（不含产品销售提成、不含团队/区域利润、不含公司利润池） |
| 「股东」性质   | **虚拟分红权**——只分钱，不涉及工商股权变更                                |
| 分档依据       | **按累计业绩自动分档**（服务单量/金额），无人工干预                       |
| 结算周期       | **月结，公司代扣代缴个税**                                                |
| 税目           | **劳务报酬所得**（第三轮确认）                                            |
| 「服务费」口径 | **服务净值**——扣除农资成本后的服务部分（第三轮确认）                      |

## 2. 法律性质与命名规范（重要）

**结论：这是「虚拟分红权」，不是股权。**

必须执行的命名与表述约束：

| 禁止使用                       | 应当使用                                     |
| ------------------------------ | -------------------------------------------- |
| 股东、股权、入股、股份、分红股 | **合伙人权益**、**虚拟分红**、**合伙人档位** |
| 股东分红、股权分红、股权激励   | **合伙人服务分成**                           |

**理由**：纪要中的「让新农人成立股东」在未做工商登记前不构成股东身份。若对外文件、界面、合同中出现「股东/股权」字样，会被理解为**股权承诺或变相集资**，产生法律与监管风险，且与实际法律关系不符。

**关系性质**：技师与平台为**灵活用工/合作关系，非劳动关系**。这一点直接决定税目（见 §5），也决定不能出现「工资」「薪酬」等表述。

## 3. 计算基数

```
月度应发分红 = Σ(当月「已完成并验收」工单的服务费) × 档位系数 − 服务质量扣减
```

**基数口径必须明确（否则结算必然扯皮）**：

| 情形                                                           | 是否计入              | 说明                                    |
| -------------------------------------------------------------- | --------------------- | --------------------------------------- |
| 工单状态 = `completed`（农户已验收）                           | ✅ 计入               | 唯一计入口径                            |
| 工单状态 = `prescription_issued` / `checked_in` / `dispatched` | ❌ 不计入             | 未完成，跨月完成的按下月计              |
| 工单状态 = `exception`（异常/超时）                            | ❌ 不计入             | 处理完毕后转 `completed` 再计           |
| 已验收但发生在次月                                             | 按下月计              | 以**验收时间**归属月份，不以报单时间    |
| 退单、返工、投诉成立                                           | ❌ 不计入             | 若已发放，在次月扣回                    |
| 技师许可证当月过期                                             | ❌ **该月全额不计入** | 联动 R5：无证期间不得作业，自然不得分成 |

> **「服务费」口径已确认为「服务净值」**（扣除农资成本后的服务部分，不含农资销售金额）。
>
> **由此产生一项数据模型要求**：工单必须**分别记录「服务净值」与「农资金额」**——原型只有一个 `settlementAmount`（单笔总额），**不足以支撑此口径**。农资成本如何在多品类、多批次间分摊到单张工单，需在第 4 步数据字典中定义（见 §9 待确认 #2）。

## 4. 分档规则（建议值，待确认）

**依据**：滚动 12 个月累计已完成服务费（自动计算，无人工干预）。

| 档位       | 滚动 12 个月累计服务费 | 档位系数 | 说明             |
| ---------- | ---------------------- | -------- | ---------------- |
| 预备合伙人 | < 5 万                 | 1.00     | 新入库技师默认档 |
| 一级合伙人 | ≥ 5 万                 | 1.10     |                  |
| 二级合伙人 | ≥ 15 万                | 1.20     |                  |
| 三级合伙人 | ≥ 30 万                | 1.30     | 封顶档           |

**设计说明**：

- 原型里的档位名（钻石/黄金/白银/预备期）与系数（1.35/1.25/1.10/1.00）**全部作废**——它们是原型生成时编造的，无任何业务依据。
- 系数上限建议 **1.30**：`1.35` 意味着平台把服务收入的 135% 发给技师，除非服务费口径里已含高毛利农资，否则模型不成立。**这一点必须与财务核对。**
- **升降档生效时点**：建议「达到阈值即时生效、次月结算时按新档计算」，避免月初月末刷档。
- **降档保护**：建议设「一次降档只降一级」且需连续 2 个月低于阈值，避免业绩波动导致收入骤降、技师流失。

## 5. 税务处理（税目已定为**劳务报酬所得**）

**结论**：按劳务报酬所得，由公司代扣代缴。

**劳务报酬预扣规则**（**需财务复核**——个税政策会调整，以下为按现行常见口径的整理）：

- 每次收入 ≤ 4,000 元：减除费用 800 元；> 4,000 元：减除 20% 费用
- 应纳税所得额适用**三级预扣率**：≤ 20,000 元 → 20%；20,000–50,000 元 → 30%（速算扣除 2,000）；> 50,000 元 → 40%（速算扣除 7,000）
- 年度终了由技师**汇算清缴**，多退少补——**系统只负责预扣，不负责汇算**

**技术约束**：

1. 税率表、减除标准、速算扣除数**必须可配置**，禁止硬编码（政策会变）；
2. 税额计算必须**以「分」为整数**，禁止浮点（R7）；
3. 税额计算必须有单元测试，覆盖边界：**恰好 4,000 元**、恰好 20,000 / 50,000 元级距临界、0 收入、异常值校验；
4. 结算单需同时输出**应付金额、预扣税额、实发金额**三项，并满足 `应付 − 预扣 = 实发`（R7 分位校验）。

## 6. 发放

- 周期：自然月，次月 N 个工作日内（N 待定）
- 通道：银企直联批量代发（原有设计已按此表述，见待决策 D2）
- 需生成两张凭证：**应付明细**（技师长按）× **代扣税明细**（财务/税务用）
- 发放失败必须可重试且幂等，禁止重复发放

## 7. 风控与管理

| 风险                                                  | 控制措施                                                                                                                                                            |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 刷单冲档（同农户反复下单、异常时段集中下单）          | 监控同农户 30 天内重复报单、同技师单日异常单量；命中转人工复核                                                                                                      |
| 服务质量差仍拿高分                                    | 服务质量扣减项（**但必须同时提供申诉通道**，否则等于单方扣款）                                                                                                      |
| 无证期间作业                                          | 与 R5 联动：许可证过期即不可接单，自然无分成                                                                                                                        |
| 成本失控                                              | 设「单人月度分红封顶」（建议值待定），超出部分转入下月或不计                                                                                                        |
| 档位计算争议                                          | 档位计算过程必须可在后台查询（累计值、阈值、生效时间），不做黑盒                                                                                                    |
| **审核 + 结算由同一人（运营管理员）兼任，缺岗位制衡** | ⚠️ 该风险已由业务方接受。**强制缓解措施**：全部审核与结算操作必须写**审计日志**（操作人、时间、对象、变更前后值），支持事后追责；结算发起与作废须留痕且不可静默删除 |
