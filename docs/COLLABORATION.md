# 华农智服 · 一人项目协作框架

> **效力**：本文件是 [`AGENTS.md`](../AGENTS.md)（项目宪法）之下的**操作框架**，规定"一人开发 + AI 代理协作"模式下，宪法中的多人角色与流程如何改编落实。红线规则、代码规范、目录约定以宪法为唯一真源；冲突时以宪法为准并须回改本文件。
> **生效**：2026-10-04，经 [ADR-0001](decisions/ADR-0001-一人项目协作框架.md) 采用。
> **改编原则**：减掉的是人与人之间的仪式（评审人、PR 队列、会议），保留的是证据（门禁输出、回归基线、书面决策记录）。

## 1. 角色模型：一人多帽

| 宪法中的角色 | 一人项目现实 | 职责落实方式 |
| --- | --- | --- |
| 产品经理（PM） | 同一人 | 需求优先级落 `docs/requirements/`；对客户的分层提问按 [`requirements/discovery-questions.md`](requirements/discovery-questions.md) 执行 |
| 需求 / 业务分析 | 同一人 + AI 起草 | AI 代理可起草 PRD / 问卷 / 信息架构，**定稿权在人** |
| 技术负责人（架构） | 同一人 | 契约冻结与红线豁免仍须**书面**——落 ADR（见 §2），禁止口头或聊天记录豁免 |
| 前端 / 后端开发 | 同一人 + AI 代理为主力执行 | 代理按宪法实施；人负责方案裁定与验收 |
| 测试 / QA | 同一人（换帽子） | "测试失败判定权、可否决合并"改编为：门禁 + 自评审清单（合并前）+ 缺陷先补用例再修（合并后），见 §4 |
| 运维 / SRE | 同一人 | 当前无生产环境，职责 = 开发环境健康与可复现初始化；发布 / 回滚决策落 ADR |
| AI 编码代理 | 一个或多个代理会话 | 无红线豁免权（宪法原文有效）；失败如实上报；协作协议见 §5 |

**关键不变量**（任何改编不得触碰）：

1. 红线 R1–R10 不因一人模式放宽；AI 代理**无红线豁免权**。
2. 一切豁免、契约冻结、破坏性变更必须落 ADR——"技术负责人书面批准"在单人模式下 = 开发者本人签署 ADR。
3. 对外（客户）表述永远遵守 [`PROJECT-SPEC.md`](PROJECT-SPEC.md) 附录 A 的结论口径：当前交付的是界面与交互框架 + 种子 Mock 后端，没有任何真实后端能力，不得表述为"已上线"。

## 2. 决策管理（ADR-lite）

- 目录 `docs/decisions/`，命名 `ADR-<三位序号>-<slug>.md`，模板 [decisions/template.md](decisions/template.md)。
- **必须落 ADR 的决策**：红线豁免；接口契约冻结与破坏性变更（R3）；技术选型 / 框架变更；新增或删除依赖；PROJECT-SPEC §7 待决策项（D1–D8）逐项裁定；AGENTS.md / PROJECT-SPEC / 本框架的条款修订。
- 一条 ADR 回答一个问题：背景 → 选项 → 结论 → 影响 → 验证方式。结论一经签署不改写——推翻旧决策用新 ADR 标注 `已取代（被 ADR-XXXX）`。
- AI 代理可以**起草** ADR，**签署权**在开发者。

## 3. 开发工作流

改编自 [`PROJECT-SPEC.md`](PROJECT-SPEC.md) §6.2 的 11 步流水线：单人无评审人，第 8/9 步（PR 评审、CI）改编为自评审 + 本地门禁，其余保留。

| 环节 | 一人模式执行 |
| --- | --- |
| 需求输入 / PRD | 不变；AI 起草、人定稿；客户确认前置（宪法"前提状态"）不变 |
| 契约与状态机冻结 | 不变；"冻结" = 落 ADR |
| 开发 | AI 代理为主力执行，人做方案裁定与关键路径把关 |
| 自测 | 门禁全绿（§4）+ 手工走通主路径与 ≥1 条异常路径 |
| 评审（原 PR + 1 人评审） | **附录 A 自评审清单**逐项勾选，证据贴进合并提交说明；可选：另开一只读 AI 会话做 second-opinion 评审（不替代清单） |
| CI（原流水线） | CNB 部署流水线已接入（2026-10-04：main push → 门禁 → 后端镜像 → 自动部署，见 [`DEPLOYMENT.md`](DEPLOYMENT.md)）；自评审清单转为 CI 配置的验收依据 |
| 验收 | 按 Given-When-Then 逐条；QA 判定权改编见 §4 |

分支纪律：

- `main` 保持可发布。业务改动一律走 `feat/*`、`fix/*`、`refactor/*` 分支，自评审通过后自行合并；`docs/` 与 `chore:` 小改可直接进 `main`。
- **WIP = 1**：同一时间只推进一个业务分支；收尾（合并或 baton 交接）后再开下一个。
- 提交纪律不变：Conventional Commits；一个提交只做一件事；重构与功能变更不混合。

## 4. 质量门禁（替代第二双人眼）

| 门禁 | 命令 | 时机 | 红线 |
| --- | --- | --- | --- |
| 类型检查 | `npm run lint` | 每次合并前 | R1 |
| 构建 | `npm run build`（`-w` 可按工作区） | 每次合并前 | R2 |
| 接口回归 | `scripts/capture-api-baseline.mjs` → `compare-api-baseline.mjs`（0 不一致）+ `smoke-mutations.mjs` | 后端结构 / 口径改动，改前改后各一次 | R3 |
| 代码质量 | `npm run lint:eslint` + `npm run format:check` | 每次合并前 | — |
| AI 层契约 | `services/ai` pytest | `services/ai` 改动时 | — |
| 单元 / E2E | Vitest / Playwright（未接入） | 接入后并入本表 | R9 |

**QA 判定权的改编**（宪法"测试失败判定权，可否决合并"）：

- 合并前：自评审清单即 QA 检查单，未全勾不得合并。
- 合并后：发现门禁覆盖不到的缺陷——**先补测试用例 / 回归夹具，再修**，禁止裸修；影响对外口径或资金 / 合规语义的缺陷直接 revert。

**例外登记**（门禁红灯期间的执行口径，解除须 ADR）：

- 2026-10-04 起 `npm run lint` 因 `apps/technician` 48 个类型错误整体红灯（该应用并入时依赖从未安装、未过类型检查，详见 [ADR-0002](decisions/ADR-0002-technician-类型债处置.md)）。红灯期间 lint / build 门禁按工作区拆分执行（`-w @hnhall/admin -w @hnhall/mall -w @hnhall/server`；`@hnhall/shared` 为纯类型包、无独立脚本），technician 单独跟踪，**不视为门禁通过**。
- 其余存量违规见宪法「存量违规登记」（响应层浮点金额等），口径不变。

## 5. AI 代理协作协议

1. **指令唯一真源**：代理只认仓库内文档——AGENTS.md（宪法）、本框架、`docs/`。代理的跨会话记忆与仓库文件冲突时，以仓库文件为准。
2. **接管协议**：新会话先 `ls -t .baton/` 取最新交接记录（无则按宪法自行勘察），核对其中 State of Play 与真实 `git status` 后从 Next Steps 继续；工作落地后退役 baton（删除或把耐久结论并入正式文档）。
3. **交接协议**：会话带着未落地工作结束时，必须向 `.baton/` drop 一份 baton（命名 `YYYY-MM-DD-<slug>.md`；`.gitignore` 已覆盖，不入库；格式见 baton 技能文件）。
4. **证据纪律**：一切"完成 / 通过"结论必须附命令与真实输出（含退出码）；禁止用管道吞掉退出码（宪法注意事项 15）；禁止伪造通过证据。
5. **上报纪律**：无法满足红线时如实上报并停下，禁止放宽校验、跳过测试、静默降级（宪法注意事项 14）。
6. **单写者约束**：同一时间只允许一个代理会话持有工作区**写权**；并行多代理仅用于互不相交的只读任务（检索、评审、基线比对），避免并发写冲突。

## 6. 外部协作（客户 / 监管）

- 客户是唯一外部干系人，也是当前最高优先阻塞项：需求确认前 PRD 不得定稿（宪法"前提状态"）。提问严格按 [`requirements/discovery-questions.md`](requirements/discovery-questions.md) 分层推进——上一层不确认不问下一层；65 题问卷仅内部备查、不外发。
- 监管接口申请（D1）、资金通道（D2）等外部依赖的进展与结论，一律落 ADR 并同步 PROJECT-SPEC。
- 对外不做口头承诺；一切进展表述走 §1 不变量 3 的口径。

## 7. 文档同步义务

实质变更时四处同步：**AGENTS.md ↔ PROJECT-SPEC ↔ 本框架 ↔ 代码 / 契约**。文档滞后按缺陷处理（先补文档再合并）。
