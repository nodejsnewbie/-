# ADR-0001：采用一人项目协作框架

- 状态：已采纳
- 日期：2026-10-04
- 决策人：开发者本人（兼技术负责人 / PM / QA 帽）
- 关联：[COLLABORATION.md](../COLLABORATION.md)；AGENTS.md「项目角色」；PROJECT-SPEC §6.3

## 背景

AGENTS.md 的角色与流程体系（PM / 技术负责人 / QA / SRE 分设、PR + 至少 1 人评审、11 步流水线）以多人团队为前提。本项目实际为一人项目 + AI 编码代理协作，多人环节不可执行；若不改编，宪法条款与现实脱节——要么空转，要么被无声绕过。

## 选项

1. 维持宪法原文，实际操作默认绕过——否决：无声绕过纪律正是宪法要防的。
2. 直接删改宪法的多人条款——否决：宪法修订应最小化，且多人条款在将来扩员时仍有效力。
3. 保留宪法原文，以操作框架改编落实方式——**采纳**。

## 结论

采用选项 3：

- 新增 `docs/COLLABORATION.md`（一人项目协作框架）：角色改编表、ADR 决策管理、工作流与质量门禁改编、AI 代理协作协议、合并前自评审清单。
- `AGENTS.md`「项目角色」追加「一人项目适配」段，指向该框架。
- `PROJECT-SPEC.md` §6.3 分支规则按一人模式修订：自评审清单替代"至少 1 人评审"；`docs/` 与 `chore:` 小改可直接进 `main`。
- 红线 R1–R10、"AI 代理无豁免权"、证据纪律**不变**。

## 影响

- 正面：流程变得可执行；豁免与关键决策有了书面轨迹（`docs/decisions/`）；AI 代理协作有了明确协议（接管 / 交接 / 单写者 / 证据纪律）。
- 代价：失去真实"第二双人眼"，以门禁 + 自评审清单 + 缺陷先补用例再修补偿。
- 扩员时：本框架废止（被新 ADR 取代），回到宪法原文多人流程。

## 验证方式

框架不改代码行为；验证 = 文档四处同步到位（AGENTS.md、PROJECT-SPEC、COLLABORATION.md、`docs/decisions/`），且下一次业务迭代按附录 A 清单执行并留证据。
